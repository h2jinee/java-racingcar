# 5단계 - 자동차 경주(리팩토링)

## 나의 학습 목표

### 1. TDD 사이클을 끝까지 지킨다.
- 테스트를 먼저 작성하고, 프로덕션 코드를 수정한다.
- Red -> Green -> Refactor 사이클을 일관되게 유지한다.
- 사이클 단위로 커밋한다.

### 2. 객체지향 생활 체조 원칙을 의식적으로 지킨다.
- 모든 원시값과 문자열을 포장한다.
- 일급 컬렉션을 사용한다.
- 한 메서드에 한 단계의 들여쓰기만 한다.
- else 예약어를 쓰지 않는다.

### 3. 주생성자와 부생성자를 명확히 구분한다.
- 주생성자는 필드 타입과 완전히 일치하는 생성자로 구현한다.
- 부생성자는 주생성자를 호출하는 방식으로 구현한다.
- 불필요한 기본 생성자는 만들지 않는다.

### 4. 책임 분리를 명확히 한다.
- Domain 객체는 View에 의존하지 않는다.
- 출력용 문자열 생성은 View가 담당한다.
- 핵심 비즈니스 로직은 Domain이 담당한다.

### 5. 이전 단계의 피드백을 반영한다.
- 같은 피드백을 반복하지 않도록, 체크리스트를 점검한다.

## 1~4단계 피드백 체크리스트

### 원시값 포장
- [ ] 비즈니스 의미가 있는 원시값은 클래스로 포장했는가?
- [ ] 유효성 검증 로직이 해당 객체 내부에 캡슐화되어 있는가?
- [ ] 검증 메서드를 생성자에서 호출했는가?

### 생성자 패턴
- [ ] 주생성자(필드 타입 일치)가 존재하는가?
- [ ] 부생성자가 주생성자를 호출하는가?
- [ ] 불필요한 기본 생성자가 없는가?

### 책임 분리
- [ ] Domain 객체가 View에 의존하지 않는가?
- [ ] 객체의 값을 꺼내지 않고 메시지를 보내는가?
- [ ] static 인스턴스 변수를 사용하지 않았는가?

### 테스트 코드
- [ ] 경계값 위주로 테스트했는가?
- [ ] 객체 단위로 비교했는가?
- [ ] 테스트용 생성자를 활용했는가?
- [ ] @DisplayName에 구체적 데이터를 포함하지 않았는가?

## 미션 요구사항

### 1. 지금까지의 자동차 경주 코드 전체 삭제
- 기존 구조나 패턴에 의존하지 않고 완전히 새롭게 출발한다.

### 2. 기능 목록 작성
- 기능을 구현 단위로 나누고
- "누가 어떤 책임을 가져야 하는가"를 중심으로 기능을 분해한다.

### 3. 아무것도 의존하지 않는 가장 작은 단위부터 TDD로 구현

## PR 전 자기 점검 체크리스트
- [ ] 객체지향 생활체조 원칙을 준수하였는가?
- [ ] TDD 사이클로 구현하였는가?
- [ ] TDD 사이클 단위로 커밋하였는가?
- [ ] 객체에게 상태를 노출시키지 않고 책임을 맡겼는가?
- [ ] 테스트는 객체의 책임과 결과만 검증했는가?
- [ ] 불변성을 최대한 유지했는가?
- [ ] 도메인 용어로 네이밍했는가?
- [ ] 협력 구조가 자연스럽게 읽히는가?

## 기능 요구사항
- 각 자동차에 이름을 부여할 수 있다. 이름은 5자를 초과할 수 없다.
- 자동차 이름은 쉼표`,`를 기준으로 구분한다.
- 주어진 횟수 동안 n대의 자동차는 전진 또는 멈출 수 있다.
- 전진하는 조건은 0에서 9사이에서 random값을 구한 후 random값이 4이상일 경우이다.
- 전진하는 자동차를 출력할 때 자동차 이름을 같이 출력한다.
- 자동차의 상태를 화면에 출력한다. 어느 시점에 출력할 것인지에 대한 제약은 없다.
- 자동차 경주 게임을 완료한 후 누가 우승했는지를 알려준다. 우승자는 한명 이상일 수 있다.

## 구현 기능 목록
### 자동차
- [ ] 이름을 통해 자동차 생성
- [ ] 이름 유효성 검증
- [ ] 현재 상태 조회
- [ ] 이동 조건에 따라 전진 또는 멈춤

### 자동차 이름
- [ ] 이름 길이 검증
- [ ] 이름 검증

### 자동차 거리
- [ ] 거리 기본 값(0) 설정
- [ ] 거리 증가(1) 기능
- [ ] 거리 값 반환
- [ ] 두 거리 중 최댓값 반환
- [ ] 특정 거리와 같은지 여부 반환

### 자동차 목록
- [ ] 쉼표(,)로 구분된 이름 문자열을 통해 자동차 목록 생성
- [ ] 자동차 목록 내 이름 유효성 검증
- [ ] 모든 자동차를 이동 조건에 따라 이동
- [ ] 모든 자동차의 현재 상태 조회
- [ ] 우승자 조회

### 우승자
- [ ] 우승자 목록 검증 (1명 이상)
- [ ] 화면 출력용 문자열 포맷팅 (쉼표로 구분)

### 자동차 경주 게임
- [ ] 자동차 목록과 시도 횟수를 통해 자동차 경주 게임 생성
- [ ] 이동 조건을 받아 한 라운드 진행
- [ ] 현재 경주 결과 조회
- [ ] 최종 우승자 조회
- [ ] 게임 종료 여부 조회
- [ ] 종료된 게임에서 경주 시도 시 예외 발생

### 자동차 경주 라운드
- [ ] 총 시도 횟수 검증 (1 이상)
- [ ] 다음 라운드 진행
- [ ] 게임 종료 여부 확인

### 랜덤 값 생성기
- [ ] 0에서 9 사이의 랜덤 값 생성
- [ ] 4 이상의 값인지 여부 반환

### 사용자 입력
- [ ] 자동차 이름 입력 받기
- [ ] 시도 횟수 입력 받기
